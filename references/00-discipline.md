# 纪律：证据、隔离、分层、诚实

这四条是全部汉化工作的地基。技术栈可以换，这四条不能换。

---

## 1. 证据等级

任何关于格式的结论，按可信度排序：

| 等级 | 证据 | 例子 |
|---|---|---|
| E1 | 运行时观测 | 实机/模拟器截图、内存断点、日志 |
| E2 | 可执行文件反汇编 | 调用方传入格尺寸 0xE，故为 14px |
| E3 | 真实资源字节 + 可复现采样 | 用 14px 网格采样得到与截图吻合的碎片 |
| E4 | 同引擎其他游戏的公开实现 | 开源读取器的结构定义 |
| E5 | 文档 / 论坛 / 推测 | "应该也是 16px" |

规则：

- **E4/E5 只能用来提出假设，不能作为结论。**
- E2 必须给出地址、指令、参数；E3 必须给出输入哈希与复现脚本。
- 报告里标明证据等级；没有 E1 就不写"实机验证通过"。

最常见的翻车：把某套资源的 E3 结论（例如正文字库 16px）推广到另一套资源（诗文 14px）。
**同一游戏内的不同资源，也可能有完全不同的格式假设。**

---

## 2. 先复现，再修复

修一个缺陷前，先做三件事：

1. **保留现场**：原资源、原产物、截图、哈希。
2. **独立复现**：写一个只依赖小快照的脚本，不依赖旧构建目录。
3. **量化吻合**：把复现结果与现象做数值比较（像素差、相关性、哈希），而不是"看起来像"。

判据：修复不是"改到不碎为止"，而是"根因被证明消除"，且用同一脚本复测得到预期。

---

## 3. 一次只改一类

把变更分成互不重叠的类别，每类一个脚本、一次提交、一份报告：

| 类别 | 不碰什么 |
|---|---|
| 提取 | 不改源 |
| 语义翻译 | 不改控制码结构 |
| 排版 | 不改语义 |
| 字库 | 不改文本 |
| 图片 | 不改文本/字库 |
| 打包 | 不做内容判断 |
| 写回 | 不做资源转换 |

好处：出问题能定位到"哪一类"；每类可单独回滚；报告里的数字有意义。

反例：翻译、换行、补字混在一个脚本里——字库字数变了，却不知道是译文变长还是排版加了字。

---

## 4. 幂等与回环

任何"解码 → 编码"必须满足：

```
encode(decode(x)) == x   # 对未修改的输入
```

这是编辑器的安全底线。不满足就不能保证"只改了我想改的字节/像素"。

实现要点：

- 保留原始块引用、调色板、对齐填充、空条目；
- 不以"重新生成"代替"原地保留"；
- 每次编辑前先跑一次回环，失败即拒绝。

覆盖对象：容器成员、纹理、字库的非目标页、未修改的包。

---

## 5. 稳定标识

翻译表的主键不能是"行号"或"文件偏移"，因为重打包会改偏移、同一句多处复用、批次合并会改顺序。

用**源内容哈希**：

```
id = sha256(原始字节)[:16]
```

收益：与位置解耦、复用自动合并、批次可乱序合并、审计可按 ID 追踪所有引用。

代价：改原文会改 ID。因此原文视为不可变；要修原文，建立显式映射，不静默重算。

## 6. 分层验证

| 层 | 问题 | 手段 | 结论措辞 |
|---|---|---|---|
| L1 结构 | 数据是否合法 | 回环、哈希、指针、组数、容量 | "结构校验通过" |
| L2 语义 | 意思是否对 | 逐句阅读、上下文、术语 | "已读 N 条，修正 M 条" |
| L3 运行时 | 游戏是否正常 | 模拟器 / 实机 | "在 X 路径上运行通过" |

禁止跨层表述：

- L1 通过 ≠ 译文正确；
- L2 读过一部分 ≠ 全量正确；
- L3 抽检通过 ≠ 所有分支正常。

**发布说明必须分别写三层，并给出未覆盖范围。**

---

## 7. 汇报模板

任何一次交付，按这五项写：

1. **改了什么**：文件、数量、范围；
2. **证据**：命令输出、哈希、报告路径；
3. **验证到哪一层**：L1 / L2 / L3，各自结论；
4. **未完成 / 风险**：明确列出；
5. **下一步**：具体动作，不写"继续优化"。

反面写法："已完成汉化""基本没问题""应该可以了"。

---

## 8. 禁止的捷径

| 捷径 | 后果 |
|---|---|
| 先全量替换再看哪里崩 | 无法定位，回归成本爆炸 |
| 字数不够就覆盖原有字位 | 未提取的 UI 出现错字 |
| 看起来对就行，不做回环 | 悄悄改坏其他字节/像素 |
| OCR 结果直接当译文 | 小字、描边、艺术字必错 |
| 批量勾选"已审" | 质量数据失真，后续判断全错 |
| 把一套网格套到所有字库 | 碎字、裁切、错位 |
| 发布说明写"完美汉化" | 与实际范围不符，透支信任 |

---

## 9. 一句话

> 格式靠证据，变更靠隔离，质量靠分层，进度靠诚实。
