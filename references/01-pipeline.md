# 通用流水线：从原盘到可玩产物

阶段划分与平台无关；每个平台专题只替换"怎么做"，不替换"先做什么"。

---

## 1. 阶段总表

| # | 阶段 | 输入 | 输出 | 验证点 |
|---|---|---|---|---|
| S0 | 源准备 | 原盘 / 安装目录 | 只读快照 + 清单 | 版本号、区域、可执行文件哈希 |
| S1 | 容器解包 | 主容器（cpk/pak/xp3/pck/apk…） | 解包树 + 条目清单 | 条目数、类型、对齐、压缩方式 |
| S2 | 文本转储 | 解包树 | `text.jsonl` + `refs.jsonl` | 找到"被指令引用"的真源，ID 稳定 |
| S3 | 翻译 | 文本表 + 术语表 | 合并后的文本表 | 控制码保留、术语一致、分批可合并 |
| S4 | 排版 | 文本表 + 引用 | 带安全换行的文本表 | 行宽上限、标点不在行首、动画文本不换行 |
| S5 | 字库 | 文本表 + 原字库 | 新字库 + 映射 | 字符集全覆盖、容量内、回环 |
| S6 | 图片 / UI | 纹理容器 + 配置 | 覆盖资源 | 未修改回环、矩形不溢出、别名全分发 |
| S7 | 重建容器 | 文本 + 字库 + 图片 | 新容器 | 条目数一致、可自解析、索引正确 |
| S8 | 写回镜像 | 原镜像 + 新容器 | 新镜像 / 补丁 | 目录记录、卷大小、大小写 |
| S9 | 增量修订 | 旧产物 + 新变更 | 覆盖层 + 报告 | 逐条旧字节比对 |

> 只想验证工具链时，不需要完整翻译。做**最小闭环**：100 条文本 → 重建 → 写回 → 启动。

---

## 2. 阶段间的硬约束

1. **S2 的 `id` 必须稳定**。改提取逻辑会改 ID，进而使所有批次失效。要改规则，先做 ID 兼容对照。
2. **S4 必须在 S5 之前**。换行会影响字符集合与字库需求；反过来做会漏字。
3. **S5 的 glyph 映射一旦分配就不能重排**。已有译文用旧别名编码，重排会让旧文本指向错误字形。必须重排时，全量重新生成映射并重编码所有译文。
4. **S7 的引用必须与文本同源**。用旧引用配新文本会把译文写到错误偏移。
5. **S9 必须验证旧字节**。每个待替换位置先按旧译文编码，与现有产物中的实际字节比对；不一致立即中止。
6. **S6 只输出声明过的文件**。未在配置中列出的资源不写，避免"复制整包"把旧版本覆盖回去。

---

## 3. 最小可运行闭环

目的：验证 S1–S8 的管线正确，不碰字库与图片。

1. 解包 → 转储 → 只翻译 100 条（含至少 1 条长句、1 条带控制码）；
2. 生成空的 glyph 映射（或跳过补字）；
3. 重建容器 → 写回镜像；
4. 启动，进入第一个对话场景，确认这 100 条显示且不崩。

闭环通过前，不要开始全量翻译。**管线没通，翻得越多亏得越多。**

---

## 4. 变更隔离与快照

每次改动前：

```sh
cp data/translation/text.jsonl data/translation/text.pre-<原因>.jsonl
cp data/translation/glyph-map.json data/translation/glyph-map.<版本>.json
```

规则：

- 一类变更一个脚本、一次提交、一份报告；
- 报告写清输入哈希、输出哈希、变更计数；
- 失败时能只回滚这一类，不影响其他类。

---

## 5. 构建报告的最小字段

```json
{
  "input": {"path": "...", "sha256": "..."},
  "output": {"path": "...", "sha256": "...", "size": 0},
  "counts": {"entries": 0, "changed": 0, "skipped": 0},
  "checks": [{"name": "entry_count_match", "ok": true, "detail": "5824 == 5824"}],
  "prepared_only": true
}
```

- 没有报告的构建视为未完成。
- `prepared_only: true` 表示只生成资源、未产出最终产物，报告中不得写成"已发布"。

---

## 6. 什么时候可以进入下一阶段

| 阶段 | 进入下一阶段的条件 |
|---|---|
| S1 → S2 | 条目数可复算，随机抽 3 个成员能解出且哈希稳定 |
| S2 → S3 | 抽 20 条能按 `file + offset` 读回原文 |
| S3 → S4 | 控制码错误 0，术语表冻结 |
| S4 → S5 | 行宽分布合理，动画类文本未被插入换行 |
| S5 → S6 | 字符集覆盖 100%，容量未超，回环通过 |
| S6 → S7 | 未修改资源逐字节相同 |
| S7 → S8 | 容器可被自己的解析器完整读出，条目数一致 |
| S8 → S9 | 新镜像能启动，最小闭环路径可走 |

任一条不满足，停下来修，不要"先往前走后面再说"。

## 7. 工程初始化

```sh
python3 scripts/hh.py init ./my-project --title "某游戏汉化" --platform psp
python3 scripts/hh.py inventory ./work/extracted --out data/inventory
```

`hh init` 会生成：`AGENT.md`、`project.json`、术语表、验收清单、进度报告模板、数据目录。

随后查 `references/platforms/README.md`：

- 平台状态 S1 以上 → 读对应 `<平台>.md` 作为操作手册；
- 平台状态 **S0（stub）** → 没有平台流程可读，只能执行本文件的通用阶段，平台细节现场取证，
  并记录证据类型。**不要拿其他平台的参数顶替。**
