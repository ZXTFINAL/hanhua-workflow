# 字库：网格、容量、补字与渲染

字库是汉化里最容易被低估的一层。**三套字库用同一个假设，必然碎字。**

---

## 1. 先判断字库属于哪种模式

| 模式 | 特征 | 本 skill 证据 |
|---|---|---|
| 位图网格（grid） | 一个索引 → 页 + 格坐标；每字固定像素；图集是二进制/纹理 | **已验证**：PSP（Fate/Extra，内含三套不同网格） |
| 矢量字体（ttf/otf） | 引擎直接加载字体文件；缺字由 fallback 处理 | 未验证，无样本 |
| SDF 图集 | 字符烘焙进 atlas，带 fallback 列表 | 未验证，无样本 |
| 混合 | 正文矢量字体 + 标题图集 | 未验证，无样本 |

> 除位图网格外，其余三种本 skill 没有实测记录。遇到时只能按第 1 节的取证方法现场判断，
> 不要套用下文的网格参数。

判断依据（按证据等级）：

1. E2：反汇编里设置格尺寸/每页字数的调用；
2. E3：用候选参数采样，与截图比对；
3. E1：改一个已知字位，看游戏内是否变化。

---

## 2. 位图网格：必须同时确认三个数

| 参数 | 含义 | 缺了会怎样 |
|---|---|---|
| `cell` | 单字像素边长 | 字被裁切或留白 |
| `per_page` | 每页字位数（常为 `cols²`） | 索引跨页错位，随机位置糊字 |
| `pages` / `index_max` | 页数与运行时索引上限 | 越界读，花屏或崩溃 |

UV 计算通式：

```
idx_in_page = index % per_page
col = idx_in_page % cols
row = idx_in_page // cols
u = col * cell
v = row * cell
```

真实案例（Fate/Extra PSP）：正文 16×16 / 256 字每页 / 16 页（上限 4,096）；
诗文 14×14 / 324 字每页；ruby 9×9 / 196 字每页。**三者不可互换。**

诗文按 16×16 重建会碎成偏旁，因为运行时按 14×14、324/页采样。这类错误不会报错，只会显示错。

## 3. 补字策略：能不新增就不新增

优先级从高到低：

1. **复用已有字位**：中文与日文字形相同/可接受的字，直接指到原字位（注意字形差异）；
2. **追加到空闲区**：常见做法是用编码用户区（如 CP932 `0xE000` 起）；
3. **压缩后腾位置**：删除"已证明无引用"的旧字；
4. **覆盖原有字位**：❌ 禁止。未提取的 UI 仍在引用它，必然错字。

"已证明无引用"必须是全量证明：所有文本表 + 所有未提取资源（UI 图片里的文字不走字库，但界面标签走）。

---

## 4. 别名与映射冻结

```json
{"你": "0xE001", "好": "0xE002"}
```

- 映射一旦分配，**只追加不重排**；
- 重排必须同时重新编码**全部**译文，否则旧译文指向错误字形；
- 映射文件与文本表要同版本提交；
- 压缩字库时，若必须重排，先备份映射，再全量重生成 + 全量重编码 + 全量回环。

---

## 5. 渲染：中日字形不是一回事

用日文字体渲染中文会出现：字形偏日式（直、骨、门等写法不同）、字重不一致、标点位置不对。

做法：

- 中文汉字与标点统一用中文字体重新渲染（例：Hiragino Sans GB W6）；
- 日文原生字位保持不动，避免破坏未提取内容；
- 不要用超细字重（W3 这类），小字号会糊；
- 同一字库内不要混用两种字体渲染同一批字。

小字号（≤ 9px）尤其注意：

- 保留完整槽位，不要按"墨迹尺寸"裁槽；
- 部分假名/拉丁字母会用到最后一列/行（`g j p q y`、`ば ふ む も り`）；
- 墨迹控制在 `cell - 1`，最后一列/行透明，避免邻格串色。

## 6. 容量核算

```sh
python3 scripts/hh.py glyphs --cols 16 --pages 16 --have glyph-set.json
```

输出：唯一字符数、现有字库覆盖、缺失数、容量、是否溢出、高频字。

规则：

- 需要字符数 > 容量 → 先压缩（删无引用旧字），再考虑扩容；
- 扩容要确认运行时索引上限，不能只看文件能写多大；
- 压缩后必须重算映射并全量重编码。

## 7. 未验证路线

矢量字体（ttf/otf）与 SDF 图集的汉化做法本 skill **尚未验证**，不在此处写步骤。
需要时按 `00-discipline.md` 的取证流程在项目内先做最小闭环，再把结论以证据等级回填本节。

已知与位图网格的根本差异只有一条（属结构性事实，非平台参数）：位图网格受
**字位容量与运行时索引上限**约束，矢量字体不受字位约束但受字体文件覆盖与 fallback 链约束。
具体怎么改、改哪里，必须现场取证。

## 8. 验证清单

- [ ] 字符集 100% 覆盖（`hh.py glyphs` 缺失 0）
- [ ] 索引唯一，无两个字符指向同一字位
- [ ] 图集非空：抽 20 个字位检查像素非全透明
- [ ] 未修改页/字位逐字节相同（回环）
- [ ] 容量未超运行时上限
- [ ] 三套字库各自用自己的参数（正文/诗文/ruby 不混）
- [ ] 多副本资源已全部替换（同一字库文件可能在容器里有多份）
- [ ] 实机/模拟器抽检：长句、标点、数字、生僻字

## 9. 常见症状对照

| 症状 | 根因 | 修法 |
|---|---|---|
| 中文全是方块 | 映射有、图集没画；或页索引算错 | 检查索引→页/格→图集非空 |
| 随机位置糊字 | 网格参数错（per_page / cols） | 按运行时参数重算 UV |
| 字被裁掉一截 | 墨迹超出 cell，或按墨迹裁槽 | 墨迹 ≤ cell-1，保留整槽 |
| 升级字库后旧文本错字 | 重排了映射但旧译文没重编码 | 全量重编码 + 回环 |
| 未提取 UI 出现错字 | 覆盖了仍被引用的日文字位 | 只追加，不覆盖 |
| 部分章节正常、部分碎 | 同一字库有多份副本，只换了一份 | 按哈希找全部副本 |
