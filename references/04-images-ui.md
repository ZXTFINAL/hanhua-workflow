# 图片与 UI：先证明可回环，再改像素

图片汉化的失败方式很集中：**改完花屏、没改的资源被旧版本覆盖、OCR 把图标当字擦掉。**

---

## 1. 先盘点，再动手

不要一上来就批量替换。先产出一张表：

| 字段 | 说明 |
|---|---|
| 资源路径 | 容器内路径 + 别名路径 |
| 文件哈希 | 用于识别重复副本 |
| 尺寸 / 格式 | 索引色 / 调色板 / 压缩方式 |
| 文本矩形 | `x, y, w, h`（像素） |
| 原文 | 日文 |
| 译文 | 中文 |
| 状态 | 待处理 / 已处理 / 保留 |

盘点结果存 JSON，脚本只执行配置，不硬编码文案。

---

## 2. 定位文字：OCR 只用来提候选

流程：

1. 解码纹理 → PNG；
2. 跑 OCR 得到候选 bbox；
3. **人工对照 PNG 确认矩形**：是否包含图标、边框、英文装饰；
4. 只擦声明区域，保留按钮、边框、装饰线；
5. 文本超出声明矩形 → 渲染器应拒绝，不要自动缩字号糊过去。

反例：只信 OCR 的 bbox，把设置界面的齿轮图标当文字擦掉。

---

## 3. 三类重点资源

| 类型 | 特点 | 注意 |
|---|---|---|
| 启动声明 / 版权页 | 大段文字、常带描边 | 描边宽度要一致，否则一眼假 |
| 教程页 | 页数多、文字与截图混排 | 截图内部的 UI 是原游戏画面，不是运行时纹理，要单独处理 |
| 小图 / 按钮 | 数量多、重复率高 | 按整文件哈希分组，改一份分发到所有别名 |

教程截图里的字**不会**因为改了 UI 纹理就变中文。报告里不能声称已全译。

---

## 4. 别名分发

同一个 TXB/纹理包可能在容器里有多份完全相同的副本（不同场景各带一份）。

做法：

1. 按整文件 SHA-256 分组；
2. 每组只编辑一份；
3. 输出时分发到该组所有路径；
4. 只输出**声明过**的文件，避免"复制整包"把其他场景的旧版本覆盖回去。

真实案例规模：466 个目标 → 260 个别名包分发。漏分发 = 某些场景仍是日文。

---

## 5. 回环是编辑的前提

```
decode(tex) → encode → 与原始字节逐字节比较
```

不通过就不允许编辑。原因：

- 调色板长度、CCT 空块计数、对齐填充、重复块引用，任何一处处理不同都会改坏未修改的图；
- 这类损坏不会立刻报错，而是在某个场景花屏。

配套检查：

- 输出容器再解析：条目名、顺序、尺寸、调色板逐项与原文件相同；
- 每个编辑目标的索引图与预期像素一致；
- 未修改块保持原引用，不重新编码。

---

## 6. 配置驱动

```json
{
  "resource": "interface/status.txb",
  "texts": [
    {"rect": [40, 12, 180, 24], "jp": "ステータス", "zh": "状态",
     "font": "HiraginoSansGB-W6", "size": 18, "color": "#FFFFFF",
     "align": "left", "max_lines": 1}
  ]
}
```

好处：可 review、可 diff、可重放；文案不进代码；同一份配置能给不同语言复用。

---

## 7. 验证清单

- [ ] 未修改纹理解码→编码逐字节相同
- [ ] 输出容器条目名/顺序/尺寸/调色板一致
- [ ] 每个目标矩形不溢出，文本不压到图标/边框
- [ ] 别名包全部分发
- [ ] 视觉抽检：启动页、教程、设置、战斗 UI、道具说明
- [ ] 截图与实机对照（不是只看导出的 PNG）
