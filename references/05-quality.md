# 质量：三层验证与语境校对

覆盖率 99.99% 不代表质量合格。真正的问题集中在三类：

1. **结构性错误**：控制码缺失、指针错位、字库缺字、图片没替换；
2. **语义性错误**：人称反了、否定反了、多义词选错、引述关系错；
3. **语境性错误**：单句看没问题，放进前后文就说不通。

---

## 1. 三层验证

| 层 | 目标 | 手段 | 能证明 | 不能证明 |
|---|---|---|---|---|
| L1 结构 | 字节/格式正确 | 回环、哈希、指针、组数、容量 | 数据没坏 | 译文通顺 |
| L2 语义 | 句意/人称/术语正确 | 逐句阅读、上下文窗口、术语表 | 读过的句子正确 | 未读的句子 |
| L3 运行时 | 游戏里真的对 | 模拟器/实机走查 | 特定路径可运行 | 全部分支 |

报告必须标明结论属于哪一层。把 L1 通过写成"汉化完成"是常见误导。

---

## 2. 语境校对：按源顺序读，不按 ID

`text.jsonl` 的 ID 是哈希，按 ID 排序会把同一场景的对话打散。

```python
refs.sort(key=lambda r: (r["file"], r["text_offset"]))
```

只有按源顺序，才能看到"上一句谁说的、下一句谁回应"，才能判断：

- 省略的主语是谁；
- `付き合う` 是"配合检查"还是"交往"；
- `しか` 是"只"还是"连……都不"；
- `じゃない` 是否定、反问还是口语确认；
- 引述的"眼前"是说话人眼前还是玩家眼前。

---

## 3. 分片方法

| 规则 | 做法 |
|---|---|
| 连续窗口 | 每包取同一源脚本的连续区间（≤ 80 行源范围） |
| 前后文 | 目标窗口前后各带 ≤ 8 行 |
| 一 ID 一主位置 | 同一句在 10 个文件复用，只在最有上下文的一处精读 |
| 分 lane | 若干 lane 并行，各自独立的进度文件 |
| 三类结果 | 已读无需改 / 建议修正 / 未决 |

进度文件：

```json
{"lane":"lane 1","targets":6356,"read":1452,"fixed":138,
 "reviewed_target_ids":["…"],"reviewed_shards":["…"]}
```

**未读就是未读。** 空文件就是 0，不预填、不批量勾选。

## 4. 语义高频陷阱

| 模式 | 日文信号 | 中文陷阱 |
|---|---|---|
| 省略主语 | 无代词 | 补错人称 |
| 授受关系 | `てくれる / てもらう / てあげる` | "他给我" vs "我给他" |
| 限制/否定 | `しか…ない`、`わけではない` | 译成肯定或反义 |
| 反问 | `じゃないか`、`のではないか` | 译成否定陈述 |
| 多义词 | `付き合う`、`受ける`、`挨拶` | 按词典首义硬译 |
| 引述 | `と言っていた`、`部長の話` | 把"说的话"译成"人的事" |
| 双重否定 | `ないわけにはいかない` | 漏一层 |
| 敬语/亲疏 | `ご主人様`、`奏者` | 统一成一个词，丢掉关系 |
| 伏笔 | 重复、异常日常、姓名双关 | 当普通叙述抹平 |

做法：先标记信号，再读上下文，最后改。**不要用正则批量替换语义。**

## 5. 检索线索不是结论

对全量文本跑风险检索是有用的，但只能产生候选：

| 线索 | 用途 |
|---|---|
| 中文补了人称、日文无明显代词 | 核对省略主语 |
| ruby 双层 | 区分读音与双关 |
| `しか` 限制结构 | 查"只/连……都不"反向 |
| 异常/记忆/姓名/重复叙述 | 保留伏笔 |
| `じゃない` | 否定/反问/确认 |
| 男女分支控制 | 保留分支，不合并 |

把这些当"已确认错误"批量改，会制造新错误。

## 6. ruby 专项

双层表记有额外结构约束：

1. 统计所有 `#RUBS ... #RUBE ... #REND`；
2. 每组译文组数必须与原文一致；
3. 上下层完全同文 → 说明把读音层重复译了；
4. 缺 `#REND`、颜色码范围错位 → 结构错误；
5. 逐类决定：普通读音取消小字层 / 特殊双意保留 / 强调点按中文长度重新配点。

```sh
python3 scripts/hh.py text check   # 已内置 ruby 配对校验
```

案例规模：929 种组合全读，1,133 条修正，结构缺损 0、组数不符 0、同文组 0。

## 7. 审阅者的工作规范

对每个审阅包：

1. 读完整窗口（含前后文），不要只看目标句；
2. 标记：已读无需改 / 建议修正 / 未决；
3. 修正写入独立 JSONL（`id / zh_cn / reason`），**不直接改主表**；
4. 同一 ID 的重复引用只产生一条修正；
5. 遇到人称/否定错误，顺藤摸瓜查该 ID 的所有复用引用。

`reason` 要可复核：

- "原文 `彼女`，前句指新闻部长，故改她"；
- "`しか` + 否定，原译反义"；
- "同一 ID 在 000003 与 000016 均出现，统一改"。

不写"润色""优化表达"。

## 8. 质量指标

| 指标 | 口径 |
|---|---|
| 文本覆盖率 | 非空译文 / 总条目（不含语义判断） |
| 结构完整率 | 可编码、控制码一致、ruby 配对、指针可解析 |
| 语境精读覆盖 | 真实读过的 ID / 全量，分 lane 记 |
| 图片回环 | 未修改资源逐字节相同 |
| 实机回归 | 明确列出走过的路径，不写"已测试" |
