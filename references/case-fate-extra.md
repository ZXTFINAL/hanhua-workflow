# 案例校准：Fate/Extra PSP 汉化

这是一个**已完成最小闭环并产出可运行 ISO** 的真实工程，用来校准规模、参数与工程节奏。

> 数字来自该仓库的 `AGENT.md` 与 `docs/`。工程仍在演进，**以仓库内报告为准**，本文件只作参照，不要当成通用常量。

---

## 1. 工程规模

| 项 | 值 |
|---|---|
| 平台 / 引擎 | PSP / CRI CPK + PAK/CMP + 自研字节码 |
| 文本条目 | 19,711 唯一 ID（非空 19,709，余 2 条全角空白） |
| 正文字库 | 4,096 字 / 16 页，1,571 个别名 |
| 诗文 | 396 字；14×14 网格 / 324 字每页；12 份副本 |
| ruby | 518 字 / 3 页；1,133 条文本修正 |
| UI | 371 个 TXB / 2,598 个 TEX；466 个目标 → 260 个别名包 |
| CPK 条目 | 5,824 条 / 2,297 处理 / 2,240 包 |
| 解包树 | 15,962 文件 / 1.67 GB |
| 变更集 | 375 文件 / 71.9 MB，逐文件 SHA-256 |
| 工期 | 格式打通到可运行 ISO 约 4 天（高密度迭代） |

---

## 2. 三套字库（同一游戏，三套参数）

| 用途 | 网格 | 每页字数 | 页数 | 备注 |
|---|---|---|---|---|
| 正文 | 16×16 | 256 | 16 | 上限 4,096 |
| 诗文 | 14×14 | 324 | — | 用 16×16 重建会碎成偏旁 |
| ruby | 9×9 | 196 | 3 | 原 219 槽保留，新增 299 |

教训：**同一游戏内也不能假设网格一致。** 诗文按 16×16 重建后，采样错位，表现为"碎字"，不报错。

---

## 3. 流水线（11 阶段）

```
S0 挂载原盘（只读）→ S1 解 CPK → S2 转储文本（沿 0x3926 / 0x1530 找指针）
→ S3 翻译（211 批 × ~100 条）→ S4 排版（≤24 全角/行）
→ S5 补字（CP932 用户区，不覆盖原字位）→ S6 压缩（4,611 → 4,096）
→ S7 重建 CPK（2,048 对齐，回填 TOC/ETOC）→ S8 写回 ISO（目录 + 卷大小 + 小写文件名）
→ S9 增量修订（逐条比旧字节）→ S10/S11 图片与诗文/ruby
```

关键约束：

- `id = sha256(源字节)[:16]`，改原文会让 211 个批次全部失联；
- 排版必须在补字之前；
- glyph 别名只追加不重排；
- ETOC 原样搬运，不重建。

## 4. 质量数据（可作为"诚实汇报"的样板）

| 层 | 数据 | 结论措辞 |
|---|---|---|
| L1 | 可编码 0 失败；ruby 结构 0 缺损；200 个 TXB 回环通过 | "结构校验通过" |
| L2 | 开场 3 场景 641 ID 逐段读完（修正 59 条）；lane 1 1,452 / 6,356 | "已读 N 条，修正 M 条" |
| L3 | PPSSPP 开场/菜单/战斗抽检 | "在 X 路径上运行通过" |

**没有写"全部完成"。** 剩余 19,070 个 ID 的语境校对明确标为未开始。

## 5. 踩过的坑（可直接复用）

| 症状 | 根因 | 修法 |
|---|---|---|
| 中文只显示前几个字，后面拖日文 | 短串未清整槽 | 新串 + 零填满原槽（含 NUL） |
| 改一句，另一场景仍旧 | 同一 ID 多处引用 | 遍历全部 `pointer_offsets` |
| 诗文碎成偏旁 | 用 16×16 重建 | 14×14 / 324，UV 重算 |
| 只有部分章节正常 | `poem.pak` 有 12 份副本 | 按哈希找全部副本 |
| ruby 小字不显示 | 原字库 219 字全是假名/Latin | 扩到 518 字 / 3 页 |
| 小字缺笔画 | 按 8×8 裁切，原字用到第 9 行/列 | 保留 9×9 槽 |
| UI 花屏 | 调色板/空块计数算错 | 回环 + 按色数计算调色板 |
| 某界面被旧版覆盖 | 复用了旧解包目录 | 未变更文件从源容器读原始字节 |
| 写完黑屏 | ISO 目录记录未更新 / 文件名大写 | 更新 extent 与卷大小，恢复小写 |
| 构建成功但内容错 | 文本表与引用不同源 | 同轮生成 + 旧字节比对 |

---

## 6. 可迁移的三条结论

1. **先做最小闭环**：100 条文本 → 重建 → 写回 → 启动。管线不通，翻得越多亏得越多。
2. **一次只改一类**：文本、排版、字库、图片分开提交，出问题能定位。
3. **进度分层陈述**：L1 通过不等于译文正确，上下文读过一部分不等于全量正确。
